# 使い方

[English](../usage.md)

このページでは、翻訳の依頼、表示、取り消し、再試行、削除の方法と、送信する文章を説明します。処理の受付、継続、キャッシュの規則は[動作](behavior.md)で説明します。

## コメントのホバー

対応するコードのコメントにマウスポインターを重ねるか、カーソルを置いてZedの `editor: hover` を実行します。同じ種類・字下げの隣接した行コメントはまとめて訳し、空行やコードを挟むと分けます。ブロックコメントは一つずつ扱います。コメント記号と直後のASCIIスペース一つを除いた本文を翻訳します。

複数行のブロックコメントとdocstringは、次の余白も除いて送ります。

- `/*` のあとの、`/**` や `/*!` の残りのように `*` と `!` だけでできた1行目
- `/*` で始まるコメントでは、2行目以降の `*` の飾り。2行目以降の空行でない行がすべて、字下げを除くと `*` で始まり、その直後がスペース、タブ、行末のいずれかの場合に、字下げと `*` を除きます。直後にスペースかタブがあれば、それも1つ除きます
- 2行目からあとの行に共通する字下げと、1行目の行頭の空白とタブ
- 最初と最後の空行と、最後の行の末尾の空白とタブ

行どうしの相対的な字下げと、間の空行は保ちます。

`source_language` が `auto` の場合、翻訳先の言語ですでに書かれたコメントには、ホバーを表示しません。これを判断するのはモデルか翻訳サービスで、[翻訳先の言語ですでに書かれた文章](#翻訳先の言語ですでに書かれた文章)で説明します。サーバーが自分で言語を推測することはありません。この結果は訳文と同じように持ち、削除されるまで、同じ文章へのホバーで再利用します。CodeLensの `Translate` とコードアクションは、いつでもコメントを翻訳します。

ホバーの位置と幅はZedが決めます。上側への固定や、本文を完全に隠さない配置は保証しません。

## Markdownの選択

[プロバイダーの設定](../../README.ja.md#プロバイダーの設定)のとおりプロバイダーが使える状態で、`features.automatic_selection` が `true` の場合、Markdownの文章を選択して安定させてください。[`selection_debounce_ms`](configuration.md#タイミング)の待ち時間のあと、バックグラウンドで翻訳します。その範囲でホバーを開いて訳文を読みます。バックグラウンド翻訳の完了通知は表示しません。`source_language` が `auto` の場合、翻訳先の言語ですでに書かれた文章には、[コメントのホバー](#コメントのホバー)と同じく、ホバーを表示しません。コードアクションは、いつでも翻訳します。

コードやリンク先だけ・空白だけの選択では開始しません。コードの囲みなどを途中で切り、選択部分だけでは構文の解釈が変わる範囲も自動対象外です。囲みを含めて選び直すか、手動翻訳を使ってください。

選択した文章はコピー目的の場合も送信され得ます。

## 手動の選択翻訳

すぐに実行したい場合やバックグラウンド翻訳が失敗した場合は、コードアクションの `Translate selection to …` を使います。完了すると通知 `Translation ready. Hover over the selected text to view it.` を表示します。コードやほかの対応する文書でも使えます。選択がないときは表示しません。

先にプロバイダーを使える状態にしてください。ChatGPTプロバイダーでは、`ChatGPT account…` から接続とプラン利用の許可を行います。Anthropic APIまたはOpenAI APIのプロバイダーでは、`Anthropic API key…` または `OpenAI API key…` からキーを保存します。

## 単語の意味を調べる

1行で3語以下、64文字以下の選択は、末尾が `.`、`!`、`?`、`。`、`！`、`？` でなければ、翻訳する代わりに意味を調べます。`retain`、`take over`、識別子の `retain_completed` などです。選択範囲にマウスポインターを重ねると、単語の説明が表示されます。説明はモデルが書きます。拡張機能に辞書のデータは含まれていません。

語はUnicodeの単語境界で数えるため、空白で区切らない言語も区切って数えます。日本語では助詞や語尾も1語に数え、`保持する` は2語、`設定を保存する` は4語です。

説明には次のものを含めます。`Example:` などの見出しは英語で、意味と品詞は翻訳先の言語で書きます。

- 語
- 品詞を添えた意味（その行での意味が先頭）
- 識別子や複合語を分けた各語の意味と、全体の意味
- 例文とその訳

Markdownの自動の選択、`Translate selection to …`、`… and open in tab` で意味を調べます。次の場合は調べません。

- 文書全体を選択した場合は、`Translate document to … and open in tab` と同じく翻訳します。
- コメントのホバーで読むコメントは、1語でも意味を調べません。
- DeepL API、Google Cloud Translation、PLaMo Translateは単語の説明を書かないため、このような選択もほかと同じように翻訳します。

## ホバーでの訳文の表示

ホバーには、見出しの `Translation LSP` と、その下の区切り線に続けて訳文を表示します。`hover.header` を `false` にすると、訳文だけを表示します。[ホバーの表示](configuration.md#ホバーの表示)を参照してください。

コメント、コードの中の選択、Plain Textの訳文は、訳文の次の書式を生かしたMarkdownとして表示します。

- コードスパンと、囲みのあるコードブロック、空行のあとの字下げによるコードブロック
- `#` で始まる見出しと、`===` や `---` の下線による見出し
- `-`、`*`、`+`、番号で始まるリスト（字下げしたものも）、引用、表、区切り線
- `*` と `**` による強調と、`~~` による取り消し線
- `[文字](URL)` の形のリンクのうち、原文にあるURLへのもの

ほかの文字は、書かれたとおりに表示します。`__init__`、`--verbose`、`\d+\.\d+`、`Vec<T>`、`<!-- note -->` はそのまま表示し、引用符や `...` も組版用の記号に置き換えません。訳文の改行は、表示でも改行します。空行は、いくつ続いても1つの段落の区切りになります。段落の中の行頭の空白は表示しません。この方法で書式を生かせない訳文は、書式を付けずに各行を書かれたとおりに表示します。

リンクで開けるのは、原文にあるURLだけです。原文の中のモデルへの指示によって、原文にないリンクが訳文に入ることがあるためです。原文のURLは、`.` や対応しない `)` など、周りの文の句読点の前で終わります。訳文では、次のようになります。

- URLだけを書いた部分は、原文のURLで始まり、その後で文が終わるか、空白かASCII以外の文字が続く場合に、リンクになります。間に句読点があってもかまいません。`詳細はhttps://example.com/docsを参照` では、`https://example.com/docs` がリンクになります。
- `[文字](URL)` や `<URL>` の形のリンクは、URLが原文のURLのどれかと完全に一致する場合に残ります。
- 空白を挟まずにURLが2つ続く部分は、クエリーの中に別のURLを含むURLなども含めて、リンクになりません。

ほかのURLは、`:` の後に見えない文字（U+2060、WORD JOINER）を入れて文字として表示し、ホバーからコピーした文字にもこの文字が含まれます。コードの中のURLは書かれたとおりに表示し、リンクにしません。

`hover.format` が `"markdown"` の場合、Markdownの文書の訳文は、訳文のMarkdownのまま表示します。リンクと画像は、リンク先が原文のリンク先のどれかと完全に一致するか（同じ相対パスなど）、`#` で始まる場合に残します。

ほかのリンク先や、`https&#58;//` のようにエスケープや文字参照で分かれたURLがあると、代わりにコードブロックの中に書かれたとおりに表示します。URLだけを書いた部分は上の規則に従い、画像の代替テキストの中のURLはリンクにしません。

`hover.format` を `"text"` にすると、単語の説明を除くすべての訳文を、コードブロックの中に書かれたとおりに表示します。単語の説明は、どちらの値でも[単語の意味を調べる](#単語の意味を調べる)のとおりに表示します。

## 翻訳をタブに開く

Markdownまたはプレーンテキスト（Zedの言語名は `Plain Text`）では、`Translate selection to … and open in tab` で訳文を別タブに開けます。選択がない場合は `Translate document to … and open in tab` となり、文書全体を翻訳します。どちらも `translation_limits.input_kib.document` の上限を使い、既定は1 MiBです。クライアントには `window/showDocument` 対応が必要です。

別タブに開く翻訳は、[期限](behavior.md#期限)で説明する時間の中で完了すると開きます。長い文章でも時間は延びません。範囲単位・全件を取り消すコードアクションで止められます。元の文書を編集・閉じた場合も結果を開きません。[`document_split`](configuration.md#文書を分けて送る) を有効にすると、長い文章を部分に分けて送ります。

Markdownの訳文は一時的な `.md` ファイルとして開きます。コマンドパレットの `markdown: open preview` で整形された表示にし、必要に応じてソースタブへ戻れます。プレーンテキストの訳文は `.txt` で開きます。通常のMarkdownの開き方は変更しません。開いた訳文はその時点の内容で、原文の編集には追従しません。必要なときに再び翻訳操作を実行してください。

残したい訳文は、言語サーバーの再起動やZedの終了前に「別名で保存」してください。一時ファイルはサーバーの正常終了時に削除します。異常終了した場合はシステムの一時フォルダーに残ることがあります。別名保存したファイルは削除しません。

相対パスのリンクや画像は一時ファイルの位置を基準に解決します。元の相対パスを使う場合は、原文と同じフォルダーへ別名保存してください。

訳文はモデルの出力です。原文の中にモデルへ向けた文章があると、原文にないリンクや画像が訳文に入ることがあります。`markdown: open preview` は、`http` と `https` の画像をそのURLから読み込んで表示します。そのため、URLに訳文の一部が入っていれば、URLが指すサーバーにその部分が届きます。他人が書いた原文では、プレビューを開く前に、訳文のタブをテキストのまま確かめてください。

同じキャッシュ済み翻訳を再びタブに開く場合は、一時ファイルを再利用してその文書へ移動します。ファイルが削除された場合や保存済みの内容が変更された場合は、既存の内容を上書きせず新しいファイルを作ります。新しく翻訳した結果は別ファイルになります。一時ファイルはサーバー終了時に削除し、「別名で保存」で保存したコピーは残します。

## CodeLens

Zedの設定で `"code_lens": "on"` にすると、本文の上の行に短いコマンドを表示します。Zedの既定値は `"off"` です。Zedは同じ行のコマンドを `|` で区切って1行に並べます。

| 場所 | 表示する行 |
| --- | --- |
| 訳文のないコードのコメント | `Translate \| Settings` |
| 翻訳済みの範囲 | 72文字までの、訳文の1行目か、単語の説明の語と最初の意味（`retain — 保持する` など）と、コードでは `Settings` |
| 翻訳に失敗した範囲 | `Translation failed \| Retry` と、コードでは `Settings` |
| 翻訳中の範囲 | `Translating… \| Cancel` と、コードでは `Settings` |
| Markdownとプレーンテキストの1行目の上 | `Translation LSP: Translate in tab \| Auto-translate: On \| <アカウントメニュー> \| Zed settings` |

`Translate` は、`Translate selection to …` と同じようにコメントを翻訳します。プロバイダーが使える状態で、`selection_action` が有効なときに表示します。ホバーで翻訳先の言語だとわかったコメントも、`Translate` のままです。`Retry` は、失敗した範囲をもう一度翻訳します。どちらのあとも、行に訳文を表示します。完了通知 `Translation ready. Hover over the selected text to view it.` は、同じ範囲をコードアクションでも待っている場合にだけ出します。

翻訳済み、失敗、翻訳中の範囲は、コメントのホバー、選択、`Translate` で翻訳した範囲です。タブに開く翻訳には行を表示しません。文書を編集すると、訳文が無効になった範囲の行は消えます。編集のあとに残った行の動きは[編集のあとのCodeLensの行](behavior.md#編集のあとのcodelensの行)で説明します。

コードでは、訳文も、失敗も、翻訳中の作業もないコメントに、その本文で残した訳文があれば、その訳文を表示します。ほかの位置やほかの文書で同じコメントを訳した場合、コメントを変えない編集をする前に訳した場合、[`disk_cache`](configuration.md#ディスクキャッシュ) を有効にして起動し直す前に訳した場合です。

訳文は、ZedがCodeLensを求めたあと、少し遅れてコメントの行に出ます。そのあとは、その位置で訳した場合と同じように、ホバーで訳文を表示し、`Delete translation` で削除します。プロバイダーが使える状態で、`comment_lens` が有効なときに働きます。`translation_limits.input_kib.hover` より長いコメントと、翻訳先の言語だとわかったコメントは探しません。後者は `Translate` のままです。

訳文の1行目をクリックすると訳文の全体を、`Translation failed` をクリックすると失敗の理由をカードに表示します。カードは閉じるまで残ります。

- `Retry translating this text` で、その範囲をもう一度翻訳します。新しい訳文はCodeLensに表示し、完了通知は出しません。
- `Delete translation` で、その範囲の結果をキャッシュから削除します。
- Zedのコピーボタンは、本文をMarkdownのままコピーします。記号の前のバックスラッシュと、前後の `---` の行も含みます。

`Translate in tab` は、`Translate document to … and open in tab` と同じように文書全体を翻訳します。プロバイダーが使える状態で `document_action` が有効なときに、`window/showDocument` に対応したクライアントで表示します。アカウントメニューの項目は、`ChatGPT account…` などのプロバイダーのアカウントメニューです。`Zed settings` はZedの設定ファイルを開きます。これも `window/showDocument` に対応したクライアントでだけ表示します。

`Settings` は、`Turn off automatic translation` または `Turn on automatic translation`、アカウントメニュー、`Open Zed settings file` を表示します。削除するものがあれば、`Delete translations of this document` と `Delete all cached translations` も表示します。条件は[キャッシュされた訳文の削除](#キャッシュされた訳文の削除)で説明します。

自動翻訳をオフにすると、言語サーバーを再起動するまで、コメントのホバーとMarkdownの自動選択では翻訳を始めません。それらが始めた翻訳のうち、ほかから求められていないものは取り消します。翻訳済みの訳文はホバーに表示し、`Translate`、コードアクション、タブに開く翻訳はそのまま使えます。Markdownとプレーンテキストの上の `Auto-translate: On` でも同じようにオフにでき、表示は `Auto-translate: Off` に変わります。

コメントの多いファイルでは、コメントごとに行が増えます。[`features.comment_lens`](configuration.md#機能の切り替え) を `false` にすると、訳文、失敗、翻訳中のどれもないコメントには行を表示せず、メニューをMarkdownと同じように1行目の上に表示します。

## 状態表示と通知

翻訳の待機・実行中は、ステータスバー左側にスピナー（回転する処理中の印）と文字を直接表示します。`Queued: …` は待機中の件数、`Translating: …, queued: …` は実行中と待機中の件数です。同じ範囲への複数の要求は一件と数えます。その範囲のタブ翻訳は、[受付と実行枠](behavior.md#受付と実行枠)で説明する別の処理になる場合に、別に数えます。この欄はほかの言語サーバーと共有するため、別の活動が優先されることがあります。

スピナーは取り消しや時間切れを含め、作業が終わると消えます。結果は原文へのホバーで確認してください。状態表示に対応するクライアントでは、翻訳失敗・時間切れの警告が残り、再試行、キャッシュの結果の削除、文書の編集や閉鎖で消えます。これらの表示に対応しない場合も、ホバーと明示操作の通知を使えます。

明示操作の完了・失敗通知にはファイル名と行番号を付けます。自動翻訳の完了ポップアップは出しません。明示した翻訳や管理操作が失敗した場合は、エラー通知を確認してください。

文書のコメントを読み取れなかった場合は、次のどちらかの警告を表示します。同じ文書では、開き直すまで1回だけです。`<file>` はファイル名です。[コメントを読み取れなかった文書](languages.md#コメントを読み取れなかった文書)を参照してください。

| 警告 | 原因 |
| --- | --- |
| `Reading comments in <file> timed out. Comments in this file are not recognized until you reopen it. To allow more time, adjust comment_parse_timeout_ms in the settings.` | 読み取りが `comment_parse_timeout_ms` を超えた。 |
| `Reading comments in <file> failed. Comments in this file are not recognized until you reopen it.` | 読み取りがサーバーの中で失敗した。 |

## 取り消しと再試行

1件を止めるには、その範囲にカーソルか選択範囲を置き、コードアクションの `Cancel translation of lines …` を実行します。その範囲のタブ翻訳が[受付と実行枠](behavior.md#受付と実行枠)で説明する別の処理になる場合は、タブ翻訳を `Cancel tab translation of lines …` と表示するため、同じ範囲に両方のアクションが並ぶことがあります。片方を取り消しても、もう片方は続きます。

`Cancel all translations` はアカウントメニューを残してすべての翻訳を取り消します。以前の取り消しアクションを再実行しても、同じ範囲の新しい依頼には影響しません。クライアントが進捗の取り消し操作を表示すれば、それでも全件を取り消せます。

失敗範囲内にカーソルを置き、Code Actionsから `Retry translation of lines …` を選ぶと、文章を選び直さずに記録された範囲を再試行できます。利用上限で停止した後も、明示的な再試行として扱います。ホバーだけでは失敗表示を維持します。

### キャッシュされた訳文の削除

1件を削除するには訳文か失敗のカードを使います。コードでは、文書の結果やすべての結果を削除するには `Settings` を使います。Markdownとプレーンテキストでは、プロバイダーが使える状態でアカウントの操作中でなければ、コードアクションにも次の項目が表示されます。

- `Delete translation of lines N-M` は、選択が空で、カーソルが翻訳済みか失敗した範囲にあるときに表示されます。範囲が重なると、ホバーで表示できる最新の訳文を対象とし、訳文がなければ最新の失敗を対象とします。
- `Delete translations of this document` は、開いている文書にキャッシュされた結果があるとき、送った内容で引く訳文がメモリーにあるとき、または [`disk_cache`](configuration.md#ディスクキャッシュ) が有効なときに表示されます。適用できない編集でサーバーが文書の本文を失ったあとは、削除できるものがないため表示しません。`Delete all cached translations` は表示します。
- `Delete all cached translations` は、いずれかの文書にキャッシュされた結果があるとき、または上と同じ2つの場合に表示されます。確認カードで `Delete` を押すと、キャッシュ全体と、ほかのプロバイダーやモデルの分も含めた、ディスクのものまでのすべての残した訳文を削除します。確認を開いたまま翻訳やメニュー操作を続けられます。

各コマンドが削除するものは次のとおりです。

- 1件の削除（カードの `Delete translation` か `Delete translation of lines N-M`）は、その範囲と完全に一致する結果を削除します。ホバー用の訳文、タブの訳文、失敗の記録、文章が翻訳先の言語だという結果です。
- `Delete translations of this document` は、その文書の結果をすべて削除します。加えて、文書のいまの本文がいまの設定で送るものの残した訳文を削除します。文章全体と、タブが部分に分けて送るならその部分、コードではコメントの1つずつです。起動し直したあとでキャッシュに何もないときも、これらは削除します。ただし、以前に選んで訳した文章の訳文は残ります。それも削除するには `Delete all cached translations` を使います。
- `Delete all cached translations` は、確認を開いている間に入った結果も含め、すべての文書の結果を削除します。

どのコマンドも、削除する結果のもとになった、[キャッシュ](behavior.md#キャッシュ)で説明する送った内容で引く訳文も削除します。最初の2つがディスクから削除するのは `disk_cache` が有効なときだけです。`Delete all cached translations` は、`disk_cache` がオフでも、ディスクの残した訳文をすべて削除します。

削除後、コメントは次のホバーで再翻訳できます。Markdownの範囲は、選び直すか手動で翻訳します。開いている訳文タブは残り、進行中の翻訳は完了すると結果がキャッシュに入ります。

## 送信する内容

翻訳プロバイダーへ送る文章は、抽出したコメント本文([コメントのホバー](#コメントのホバー)で説明した記号と余白を除いたもの)、選択範囲、または文書翻訳を明示した場合の文書全体です。意味を調べる場合は、語のある行（語の前後それぞれ最大200文字）も送ります。

指示文を受け付けないDeepL API、Google Cloud Translation、PLaMo Translateを除くプロバイダーでは、モデルに、文章をまとまりとして、翻訳する対象だと区切って渡します。意味、コード、識別子、URLを保って訳文だけを返し、文中に指示や質問があっても、従ったり答えたりせずに訳すよう指示します。この指示によって翻訳の正確さを保証するものではありません。

訳文をJSONの断片へ分けたり、Markdownの書式や改行の違いを理由に拒否したりしません。

手動の選択翻訳・全文翻訳は、字下げやコードだけの内容でも指定した文章を送信します。Markdownの散文判定は、バックグラウンドでの自動翻訳だけに適用します。

[`document_split`](configuration.md#文書を分けて送る) を有効にすると、`chunk_kib` の1.5倍より大きく、分けられる境界がある文章の別タブに開く翻訳は、部分ごとに、それぞれを1つの文章として送ります。指示文を受け付けるプロバイダーでは、各部分の指示文に、文章が長い文書の一部であること、そのどの文も訳すこと、見出し、前置き、文を足さないことを加えます。

DeepL APIとGoogle Cloud Translationは指示文を受け付けません。サーバーは文章を区切り、コードとURLに印を付けて送り、訳文を組み立て直します。部分に分けて送る文章の各部分も同じように送ります。コードブロックは送らないため、コードだけの文章はそのまま表示します。DeepL APIのページの[送信する内容](providers/deepl.md#送信する内容)で説明します。

PLaMo Translateも指示文を受け付けないため、サーバーは文章を書かれたとおりに送ります。システムメッセージには、モデルの設定として、翻訳先の言語と、`source_language` が言語コードのときは元の言語だけを書きます。部分に分けて送る文章の各部分も同じように送ります。PLaMo Translateのページの[送信する内容](providers/plamo-translate.md#送信する内容)で説明します。

意味を調べる場合は、意味、語の内訳、例文をJSONのオブジェクトで返すようモデルに指示します。サーバーはそのオブジェクトから説明を組み立て、応答の文字列をすべてエスケープするため、応答によってホバーにリンク、画像、その他の書式が加わることはありません。そのようなオブジェクトでない応答はエラーとして報告します。コードアクションから再試行してください。

会話履歴は送りません。訳文を原文へ書き戻すこともありません。同じ依頼の訳文をサーバーがすでに持っている文章は、再試行を除いて送り直しません。[キャッシュ](behavior.md#キャッシュ)を参照してください。

### 翻訳先の言語ですでに書かれた文章

コメントのホバーとMarkdownの自動の選択では、`source_language` が `auto` のとき、指示文を受け付けるモデルには文ごとの言語も尋ねます。コード、識別子、URLは数えません。すべての文が翻訳先の言語のとき、サーバーは何も表示しません。そうでなければ訳文を表示し、訳文のない応答はエラーとして報告します。

PLaMo Translateは言語を返しません。同じ翻訳で、応答が両端の空白を除いて送った文章と同じなら、`target_language` が何であっても、サーバーは何も表示しません。モデルがそのような文章を書き換えて返したときは、応答を訳文として表示します。明示の翻訳と、`source_language` に言語を指定したときの翻訳では、応答を表示します。

指示文を受け付けるモデルには、次の場合は言語を尋ねず、サーバーはいつも翻訳します。

- 明示の翻訳と、意味を調べる依頼
- `source_language` に言語を指定したとき
- `target_language` が、`Japanese` のような言語名、中国語のコード `zh` か `zho`（地域がついたものを含む）、`zh-Hant` や `sr-Latn` のように文字の種類を含むコードのとき

DeepL APIとGoogle Cloud Translationは区切りごとに検出した言語を返し、サーバーはそのコードで、地域を除いて同じように判断します。`target_language` が中国語のコードか文字の種類を含むコードのときは、検出したコードが大文字と小文字の違いを除いて完全に一致する場合にだけ、何も表示しません。Google Cloud Translationは、`zh` と `zh-CN` を同じコードとして扱います。

自動の翻訳の応答を待つ間に、同じ範囲でコードアクションなどの明示の翻訳を実行し、その文章が翻訳先の言語だと判断された場合は、同じ文章をもう一度、明示の翻訳として送ります。

### ディスクに書くもの

[`disk_cache`](configuration.md#ディスクキャッシュ) を有効にすると、サーバーは完了した訳文を、このコンピューターの暗号化しないファイルに書きます。送った文章と、その前後の行は書きません。単語の説明には、その単語と例文が入ります。訳文には、コードや識別子など、訳さずに残したものが入ります。ファイルの中身と場所は[ディスクキャッシュ](configuration.md#ディスクキャッシュ)で説明します。

## VS Code

VS Codeでも、拡張はこのページのとおりに動きます。違うのは次の点です。

- ホバーは訳文の題名を、引用ではなく、地球のアイコンと `Translation LSP` で示します。
- 訳文の1行目または `Translation failed` を押すと、カードではなく、その行の下に文が開きます。そのボタンで、文のコピー、翻訳のやり直し、削除、閉じる操作ができます。コピーするのは、書式のための文字を足していない、届いたままの訳文です。辞書の項目はMarkdownのままです。文書を編集するか、別の訳文を開くと閉じます。
- `Settings` のメニューの `Open settings` と、Markdownとプレーンテキストの上の `Settings` は、拡張の設定を開きます。
- 文の上の行は、`日本語への翻訳` や `日本語への翻訳に失敗` のように、それが何かを示します。
- `Settings` やAPIキーのメニューは、ウィンドウの上部に一覧で開き、何のためのメニューかを題名に示します。キャッシュした訳文をすべて削除する前と、保存したキーを削除する前の問いは、`キャンセル` の付いたダイアログで開きます。

行の下に開く文は、訳文のおよそ最初の100,000文字を見せます。コピーのボタンは全体を写します。

変えた設定は、言語サーバーの再起動で反映されます。拡張は通知に「再起動」のボタンを出します。押すまでは、動いているサーバーが元の設定のまま、実行中の作業を続けます。コマンドパレットの `Translation LSP: 言語サーバーを再起動` で、いつでも再起動できます。

拡張は、[対応言語](languages.md)のすべての言語でサーバーを起動します。VS Code本体が対応していない言語は、その言語の拡張機能を入れて言語IDが付くようにすると使えます。VS Codeや言語の拡張機能が別の言語IDを付けるファイル（`.jsx` や `.kts` など）には、`features.languages` のJavaScript、Kotlin、Proto、HCLの設定がそれぞれ効きます。

拡張のボタン、設定、メッセージは、VS Codeの表示言語に合わせて英語か日本語になります。サーバーのメニュー、CodeLens、メッセージは英語のままです。
